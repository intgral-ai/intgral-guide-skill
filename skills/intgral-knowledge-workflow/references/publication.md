# docs 重大更新、通知与反馈

同时检查自动写入和登记 docs 的人工修改。按配置节奏读取实际修订及实质差异，不能把 updatedAt 改变直接当作重大更新或新决定。

重大变更：有效决定/替代决定、关键范围或验收变化、改变判断的验证结果、明确确认的负责人/期限/依赖变化、重要阻塞及解除。需要评审的提案可以通知，但必须标待确认。普通改字、排版、重复回写或仅补来源链接不单独推送。

顺序：核对来源/目标权限 → 更新 docs → 重新加载复核 → 生成通知预览 → 必要的跨受众批准 → 发送 → 查消息回执。权限漂移阻断发布；发送不明先查询现有消息，不能盲目重发。

通知包括：标题、阶段、改了什么、影响、下一步/待谁确认、受众可访问的文档链接。按稳定文档/问题 ID、修订或 payload hash、目的地去重。密集修改同主题合并一次更新，后续实质更正回复原线程；日报链接已通知事件，不原样重复播报。

私有 Decision 目的地可同时承载待确认、已决定与重大更新；用消息类型区分，一题一线程。Team 更新只到已授权团队目的地。个人和未知权限记录不发团队频道。默认关闭敏感链接预览；生成通知、回声、自己的推送或已处理反馈不能递归当作新来源。

任务、PR、验证和业务验收反馈分别表示。新的结果可以重新打开问题；只有新确认才替代决定。自动化不得凭探索建正式任务，仍按项目 work_tracking 的确认、owner、验收和去重门槛执行。
