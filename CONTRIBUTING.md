# Contributing

Keep this package portable and public-safe. Current company facts belong in authorized private context; workflow improvements belong here.

1. Open a branch or fork and make the smallest useful change. Use synthetic examples and generic roles.
2. Update the publication allowlist in `scripts/validate.py` when a new public file is genuinely needed. Preserve links from `SKILL.md` to conditional references.
3. Run both checks documented in the README. Use a GitHub noreply commit email when keeping your personal email private.
4. Open a PR with the problem, changed behavior, validation and public-data review. Avoid internal evidence links, customer records and private screenshots.
5. Merge after the required check, an independent approving review and resolution of conversations. New changes require fresh review; keep the branch current with main.

Repository write access permits contribution and review, not bypassing the protected main branch. Organization administrators manage access. Changes to roles or access need an explicit authorized request and a verified target account or team.

For workflow changes, try realistic requests: a missing private configuration, a customer request with incomplete evidence, a Figma-dependent UI decision, a handoff with failed validation, and an explicitly requested archive. Confirm the guidance preserves unknowns and does not turn an advice request into external mutations.

Describe the observable result in the PR. Static validation does not establish that a language model passed these behavioral cases.
